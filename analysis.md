
# Day 1 Assessment: Comparing a Plain Chatbot, Rule-Based Workflow, and AI Agent

## 1. Introduction

The aim of this task is to compare a plain chatbot, a rule-based workflow, and a tool-using AI agent using a private-data scenario. The selected scenario is a college course-fee assistant that helps students find course fees and identify course combinations within a given budget.

The three systems solve the same problem using different approaches. A plain chatbot mainly generates responses using a Large Language Model (LLM). A rule-based workflow follows predefined steps and conditions without using an LLM. An AI agent combines an LLM, tools, and an execution loop to interpret a request, select tools, observe their results, and continue working until the task is completed.

## 2. Selected Scenario

The selected scenario is a college course-fee assistant. The college has the following course-fee information:

| Course Code | Course Fee |
|---|---:|
| CS101 | Rs. 12,000 |
| AI202 | Rs. 18,000 |
| DS303 | Rs. 15,000 |

This information represents private college data. Students may ask about course fees, compare courses, calculate fees, or find two courses that fit within a given budget.

For example, a student may ask, "I can pay Rs. 30,000. Which two courses can I take together within this budget?" This question requires accessing course-fee information, calculating possible combinations, and checking whether the totals fit within the budget.

## 3. Explanation of Each Approach

### 3.1 Plain Chatbot

A plain chatbot receives a user's question and sends it to an LLM to generate a response. It mainly relies on the model's learned knowledge and the information provided in the conversation or prompt. In this implementation, the chatbot does not directly access the college's private course-fee data through tools.

The chatbot does not require predefined workflow rules or external tools to generate a response. It processes the user's message and returns an answer generated by the LLM. However, when asked about private course fees, it may not know the correct values unless the information is provided to it. It may also produce incorrect or unsupported information.

Therefore, a plain chatbot is useful for general conversations and explanations, but it is limited when accurate answers depend on private or specific data.

### 3.2 Rule-Based Workflow

The rule-based workflow uses predefined Python steps and conditions to process a user's request. It does not involve an LLM in its decision-making process. It uses programmed rules and the available course-fee information to answer supported questions.

When a user asks a question, the workflow checks whether the request matches a condition it has been designed to handle. It then performs the corresponding steps and returns a result. For example, it can retrieve course fees and perform calculations when the relevant rules are implemented.

The main limitation is that the workflow can only handle cases covered by its predefined rules. If a user asks an unfamiliar question or requests a task that has not been programmed, the workflow may fail or return a message that it cannot handle the request.

In this scenario, the workflow may not solve a new multi-step question, such as finding all possible course combinations within a budget, unless a specific rule has been implemented for that task.

### 3.3 AI Agent

The AI agent combines an LLM, tools, and an execution loop. It uses the LLM to interpret the user's request and decide which tools may be needed. The tools provide access to the required course-fee data and calculations.

In this project, the agent can use a course-fee lookup tool to retrieve fees and a calculator tool to perform arithmetic. The agent receives the user's request, selects the appropriate tools, observes their results, and uses those results to continue processing the task until it can provide an answer.

For the budget question, the agent can retrieve course fees, calculate possible combinations, compare the totals with the budget, and present combinations that fit. This allows it to handle a multi-step task more flexibly than a fixed workflow.

However, the agent depends on the correctness of the LLM's decisions, the available tools, and the data returned by those tools. It may select an inappropriate tool or produce an incorrect result if tool use or reasoning fails. Therefore, its results should be checked for important decisions.

## 4. Comparison Table

| Basis for Comparison | Plain Chatbot | Rule-Based Workflow | AI Agent |
|---|---|---|---|
| Flexibility | Flexible in conversation, but may not know private fee data. | Limited to predefined rules and supported inputs. | Can adapt its tool use to different requests. |
| Decision-making | Generates responses using the LLM. | Follows fixed conditions and steps. | Uses the LLM to select tools and decide next steps. |
| Tool usage | No external tools in this implementation. | Uses programmed functions or steps where required. | Selects and uses tools, such as fee lookup and calculator. |
| Private-data access | Cannot directly access private fee data unless provided to it. | Can access data included in or connected to its programmed logic. | Can access private data through authorized tools. |
| Multi-step task handling | May explain a task but cannot reliably perform data-based steps without the required information or tools. | Handles only multi-step tasks explicitly programmed. | Can coordinate multiple tool calls to complete a task. |
| Automation | Mainly generates a response to the user's message. | Automates predefined tasks consistently. | Can automate tasks requiring flexible tool selection and multiple steps. |
| Reliability | May generate unsupported or inaccurate answers. | Consistent for correctly programmed cases, but limited outside them. | Depends on the LLM, tools, and data accuracy; tool use and answers need checking. |

## 5. Suitability Analysis

For the selected course-fee scenario, an AI agent is suitable for requests that require retrieving private fee data, performing calculations, and comparing multiple course combinations. It can use the fee-lookup and calculator tools and combine their results to answer a student's request.

The rule-based workflow is useful for simple, predictable tasks, such as returning a known course fee or applying a fixed calculation. It can provide consistent results when the request matches its programmed rules. However, adding new types of questions may require additional rules.

The plain chatbot is useful for general explanations about courses or for answering questions that do not require private college data. It is less suitable for providing verified course-fee information when that data has not been supplied to it.

Therefore, for a multi-step budget question involving private course-fee data, the AI agent can be a suitable approach because it can use tools and combine intermediate results. A rule-based workflow can handle fixed fee-related tasks, while a chatbot can support general conversation.

## 6. Conclusion

A plain chatbot, a rule-based workflow, and an AI agent are useful for different types of problems.

A plain chatbot is appropriate for general conversation, explanations, and tasks that mainly require natural-language responses. A rule-based workflow is appropriate for repetitive and predictable tasks with clearly defined conditions and steps. An AI agent is appropriate for tasks that require flexible decision-making, access to tools or private data, and multiple actions based on intermediate results.

This task demonstrates that an AI agent combines an LLM, tools, and an execution loop to work through a request. However, flexibility does not guarantee correctness. The accuracy of the data, tool calls, and final answers must still be checked.
